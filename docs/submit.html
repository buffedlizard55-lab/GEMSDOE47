Submission steps

  1. Open the competition and go to the Submissions tab. drivendata.org/competitions/306/ → sign in → Submit → Make new submission (the flow described on the competition page itself).
  2. Upload the file above. The page accepts a single-band GeoTIFF (.tif) or a .zip containing exactly one GeoTIFF. Do not zip this one — it is already a single GeoTIFF. Do not re-save it in another tool: re-encoding can rewrite the nodata tag, which is what caused an earlier rejection on this project.
  3. Give it a unique name / short comment so submissions can be told apart (for example, “clustering with k=25” style comments are what the form expects here): 
    d_cat annulus flank-prune, B = 20 px (2.0 km), 18,524 px, conformal floor 0.3484 @ 75%
  4. Paste the note into the optional Note field. This is the field the brief requires the conformal confidence level to appear in, so it is already inside the text: 
    Method: delete-only distance-to-catalogue annulus prune of a dot network, B = 20 px
(2.0 km). Leaves 18,524 px. Modelled DTI 0.34912; split-conformal certified floor
0.34837 at 75% confidence (3 calibration rungs with official scores, q = 0.000755,
Lei et al. JASA 2018 split conformal). Full note and limitations:
github.com/buffedlizard55-lab/GEMSDOE47 (notes/SUBMISSION_NOTE.md).
    The long-form note is notes/SUBMISSION_NOTE.md in the repository.
  5. Before you click submit, check one thing: does the competition keep your best score, or only the most recent submission? This file is a bet that the modelled 0.3491 is realised; if the board keeps only the latest submission and the bet fails, the 0.2778 you already hold is replaced. The rule is on the competition rules page — official rules. Nothing in this repository uploads anything automatically.
  6. Record the result. When the score returns, add the rung to notes/results.json and to the ladder table on the analysis page. If it comes back below 0.2778, that is the single most valuable measurement this project can get: it pins the decay rate of T, which is the one assumption the whole submission rests on.

Why we are confident about the format. The only submission this project has had rejected failed with “Predicted values must be in range [0, 1]” — that is a nodata sentinel or an out-of-range value being read as a prediction. This file eliminates both: it contains exactly two distinct values, and it declares no nodata at all, matching the format of the 0.2778 artifact that was accepted.
