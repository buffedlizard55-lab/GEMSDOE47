Gate 1 — scientific promotion (required before packaging)

  1. Pin authorized input files, the candidate code revision, the frozen protocol and spatial block assignment by SHA-256. Distinguish official downloads from public mirrors and verify labels/grid semantics.
  2. Show that the candidate is genuinely new—not a copied mask, pruned prior raster, or renamed artifact—and compare it to accessible prior TIFFs. Report the search coverage and what cannot be searched.
  3. Evaluate against the current reproducible spatially blocked holdout best with disjoint guarded folds (at least 300 m for this 100 m grid), equal mass or a justified alternative, pooled and per-fold metric values, and meaningful random/domain controls.
  4. Require the candidate to beat the holdout best and controls under the preregistered rule with adequate labelled coverage. A tie, failed control, empty/unstable evidence, or unsupported conformal floor closes the gate. Public leaderboard values do not replace this test.
  5. Report limitations, including public-catalogue bias, spatial dependence, missing blocks, and the gap between public labels and expert-private target labels.

Gate 2 — verify the exact output bytes

  1. Build a new single-band GeoTIFF from the promoted prediction using the official sample-submission profile. Do not modify a previously submitted TIFF to imitate a new model.
  2. Run the local validator after writing, using the exact authorized template and the organizer-confirmed valid footprint. In this mirror, the sample/label footprint and the footprint inferred from training_features.tif disagree by 1,540 and 3,061 pixels, so do not substitute the feature-derived mask without resolving that mismatch. If the organizer's current instructions confirm that finite sample-template cells define the footprint, build and use an explicit mask:

    python scripts/build_footprint_mask.py --template sample_submission.tif --output footprint_mask.tif
    python scripts/validate_submission.py --submission prediction.tif --template sample_submission.tif --footprint-mask footprint_mask.tif --report validation.json

    The helper records hashes and derives only from finite, unmasked sample cells; it cannot authenticate the download or organizer semantics.
  3. Check width, height, CRS, transform, one-band float32 type, nodata/mask convention, and every in-footprint value in [0,1]. Reopen the final path, compute its SHA-256, and keep the validator report. A local pass is not an organizer acceptance guarantee.
  4. Choose a unique, descriptive filename and a brief truthful note. Never state that the file has a particular public score unless an organizer receipt maps that exact hash to that score.

Gate 3 — manual portal action (authorized team member only)

  1. Immediately before any upload, review the current official competition page, problem description, rules, format instructions, deadline, and participant-dashboard upload allowance. The description says one submission is selected for scoring across the initial and final prize rounds; do not infer unlimited uploads from that statement or rely on this dated repository for live rules.
  2. Sign in through the team's authorized DrivenData account and open the GEMS Prize submission page. Follow its currently displayed “new submission” workflow.
  3. Upload the verified `.tif` (or a permitted archive only if the current portal instructions explicitly allow it), enter the unique name and short note if those fields are present, and submit manually.
  4. Wait for validation/scoring to finish. Record the organizer submission/receipt ID, timestamp, exact uploaded SHA-256, status and returned score. If rejected, preserve the message and inspect the rejected bytes; do not guess at a fix or silently substitute another file.
