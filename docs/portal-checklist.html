Pre-upload checklist

  1. Confirm the selected candidate is promoted in a reproducible report: official inputs authorized, spatial blocks frozen, ≥300 m guard, matched prediction mass, fold results and controls included, and candidate beats the local incumbent under the preregistered rule.
  2. Check the final artifact is generated from the new model output, not a prior submission or placeholder. Retain exact input, code revision and output SHA-256.
  3. Run python scripts/validate_submission.py --submission new_candidate.tif --template official_sample_template.tif --features training_features.tif after writing (replace example paths with the exact authorized files). Resolve every reported error; do not clip or replace nodata blindly.
  4. Confirm exactly one float32 band; official width, height, CRS, transform; finite in-footprint pixels all in [0, 1]; and NaN outside the footprint. Re-open the exact bytes that will be uploaded.
  5. Confirm name and short note accurately reflect this model, new inputs and any limits. Keep the SHA-256 receipt.
  6. Use the authorized DrivenData submission portal manually; verify the portal's receipt and record the result. The project does not automate access or use a weekly slot.

Known limits

Public participant-level leaderboard values do not identify a TIFF. The label set used in a spatial catalogue holdout cannot stand in for expert-private newly mapped faults. A passing format check does not prove geological skill; a holdout gain does not guarantee private/final ranking. See the irregularity register and next-session plan.

Always verify the current official instructions and competition rules before submission.
