2 · A bounded assessment of the reported 0.2778

The metric rewards precision: sparse pruning can raise DTI when it removes low-credit evaluated mass faster than it reduces earned kernel credit. The owner-reported trajectory 0.1922 → 0.2477 → 0.2600 → 0.2708 → 0.2778 is consistent with that pattern, but the public 0.2778 participant row is not linked to a TIFF hash, and the H33-2-B2 page says UNSCORED. If the organizer excludes catalogue pixels from both score sums as the staff wording suggests, deleting only those pixels would not change DTI; exact implementation is not independently verified. See the bounded causal assessment.

Range-safe output and limits of the reported error

The previously rejected TIFF and exact portal response are not available, so its root cause cannot be confirmed. A bounded scan of 29 sibling GeoTIFFs (evidence/range_error_diagnosis.json) does show that NaN pixels fail a NaN-intolerant [0,1] check, while the scanned all-finite variants pass.

ConventionFiles scannedOut-of-footprint pixels np.all((v>=0)&(v<=1))Any value outside [0,1]?
-nan (nodata = nan)127,111,787 NaN FAILS — 12 / 12No

Mechanism. NaN fails both comparisons in (v >= 0) & (v <= 1), so any validator written that way rejects the file even though every real value is exactly 0 or 1. Several sibling sites offered the -nan file as the primary download.

Fix applied. The primary download here is the all-finite variant: float32, one band, EPSG:32611, 100 m, template-matched geotransform and bounds, 0.0 outside the footprint, no NaN anywhere, nodata unset. src/gems47/submission.py writes both variants and its validator runs every plausible range reading separately, reporting which ones pass.

Owner-reported score associations include both -nan and all-finite files, but no organizer receipt maps those rows to exact file hashes. This does not prove that both conventions are accepted by the current portal. The all-finite variant passes every local reading we could construct, which is why it is the research-download default; organizer acceptance remains unverified.

Why the 0.6081 in the F2 column must not be believed. F2 is arm 2’s own belief model. A candidate chosen to maximise a fitted objective, then scored by that same objective, always wins. Measured directly: the in-fold advantage was +0.51 / +0.52 DTI and it collapsed to −0.061 / −0.045 when the candidate was scored by a model fitted on the other fold. That ≈0.30 gap is the optimizer’s-curse plus pool-selection premium, and it is the single most important number on this site. See cross-fitted validation.
