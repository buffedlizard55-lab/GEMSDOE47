Read this before you submit anything

This project did not produce a candidate that beats the incumbent on any local frame — and it says so plainly rather than dressing the result up.

Both GEMSDOE47 arms were scored against five independent truth frames. The live-0.2600 incumbent beat both of them on all five, including on the one quantity that needs no truth model at all (the covered 300 m kernel integral: incumbent 341,261 vs 219,259 and 99,916). A cross-fitted test — the only test that can honestly rank a new candidate — returned −0.0611 and −0.0450 in the two folds.

The project rule is “never spend a weekly submission slot on an idea that hasn’t beaten the current holdout best.” That rule is binding here. Recommendation: do not use a weekly Development Round slot on either arm. What this repository contributes

1 · A working leaderboard instrument

Twelve prior submissions were recovered byte-exactly, together with the DTIs the organiser returned for them. LATI (Leaderboard-Anchored Truth Inversion) treats those twelve numbers as measurements of the hidden label set and inverts them for the truth’s intensity field. It is exact in T, first-order-corrected in Φ, 700× faster than the dense path, and it comes with positive and negative controls.

→ the method

2 · A measured answer to “why 0.2778”

It is not a discovery, it is precision. From 1/DTI = 0.2 + 0.2·(F/T) + 0.8·(K/T) the score is governed by the ratio of wasted mass to earned credit. Every step of 0.1922 → 0.2477 → 0.2600 → 0.2708 → 0.2778 cut emitted mass S faster than it cut earned credit T. The 0.2778 arm additionally deleted every dot sitting on a masked catalogue pixel — mass that can never earn and always costs α per unit.

→ the arithmetic

3 · A real fix for the upload rejection

29 sibling GeoTIFFs were scanned. 12 of 12 -nan variants fail np.all((v>=0)&(v<=1)); 17 of 17 all-finite variants pass it. No file anywhere had a value outside [0, 1]. The defect is NaN, not range.

→ the diagnosis

4 · Two falsified hypotheses, quantified

The catalogue-flank idea looked excellent on twelve observations (+55.7 % LOO, 67 % of the hidden mass within 150 m of a mapped fault, ×19.5 enrichment). One extra observation — the flank-pruned 0.2778 raster — inverted it. Break-even: the flank is only real if that file scored ≤ 0.2200. It is reported at 0.2778.

→ all five hypotheses, ranked

The "Predicted values must be in range [0, 1]" fix

The reported rejection was reproduced and diagnosed by scanning every GeoTIFF the sibling repositories published (evidence/range_error_diagnosis.json).

ConventionFiles scannedOut-of-footprint pixels np.all((v>=0)&(v<=1))Any value outside [0,1]?
-nan (nodata = nan)127,111,787 NaN FAILS — 12 / 12No
-zeros / all-finite170.0, no NaN anywhere PASSES — 17 / 17No

Mechanism. NaN fails both comparisons in (v >= 0) & (v <= 1), so any validator written that way rejects the file even though every real value is exactly 0 or 1. Several sibling sites offered the -nan file as the primary download.

Fix applied. The primary download here is the all-finite variant: float32, one band, EPSG:32611, 100 m, template-matched geotransform and bounds, 0.0 outside the footprint, no NaN anywhere, nodata unset. src/gems47/submission.py writes both variants and its validator runs every plausible range reading separately, reporting which ones pass.

Both conventions have historically been accepted by the portal (-nan files scored 0.2600 / 0.2477 / 0.1922 …; all-finite files scored 0.2778 / 0.1294), so the rejection is intermittent or path-dependent. The all-finite variant passes every reading we could construct, which is why it is the default.

Session 3 — scarp-persistence candidate CONTROL-PASSED · NOT LATI-VALIDATED · NO SLOT RECOMMENDED YET

A third session worked the same brief independently and is merged here under src/gems47s3/, docs/session3.html and knowledge/04..06. Its candidate is a different detector: an across-strike step in det_elev_slope, persisted 1.9 km along strike (scarp(det_elev_slope, r=9)), emitted at 2.8 px spacing, 7.37 dots per 1000 scored px and a 2 px catalogue-flank buffer — 37,612 positive px, binary {0,1}, all-finite, no nodata tag, max Jaccard 0.0144 against all 18 reference artifacts.

It passes the control that closed both gates above. At matched mass, spacing and flank buffer on identical folds it beats a uniform random field put through the identical emitter by 6.02× / 6.17× / 6.61× on the three prevalence-matched frames and 4.75× on the isolated-component frame, and beats a translated copy of itself (same density and clustering, alignment destroyed) by the same margins; A > B on 87 of 94 blocks (evidence/control/controls.json). H47-B lost that comparison (0.02755 vs 0.03716). The first run of the control reported the opposite — A/B = 0.28 — because the controls were pruned against the visible catalogue while the candidate was pruned against the full catalogue; the asymmetry, not the candidate, produced that number (IR-47-CODE-09). Both runs are recorded.

Why no slot is recommended yet. It has not been through this repository’s promotion instrument: cross-fitted LATI with paired out-of-fold deltas against the incumbent, on all five truth frames. Its own holdout shows the optimizer’s-curse signature — calibration mean 0.0968 against a selection mean of 0.0606, a 37% out-of-fold drop. It stays positive, which H47-GSA did not, but a positive drop is not a promotion. It also inherits every ceiling this README records: it is built on the same 100 m layers that forty-four repositories converged on at 0.26–0.28, and a 0.5–3 m scarp averaged into a 100 m pixel is below the noise floor of the resampled product.
