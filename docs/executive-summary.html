Submission workflow

What must happen before upload

  1. Obtain the official inputs through an authorized entrant login.

    Use the official DrivenData data page for the official feature raster (the public problem page names training_features.tif), label raster/vector, sample-submission GeoTIFF, and 1m_DEM_links.csv. The exact label/template basenames are not verified without login; use their actual downloaded paths. The data page redirects unauthenticated users to login. Do not bypass it.

  2. Freeze the incumbent and preregister H47-A.

    Record file hashes, exact grid metadata, candidate parameters and controls before scoring; use spatially disjoint blocks with a guard at least 300 m wide.

  3. Run the holdout against the incumbent at matched emitted mass.

    Report each fold, pooled distance-weighted Tversky, a domain-matched random control, and ablations. A public-catalogue holdout only screens for overfitting; private expert labels are not available for validation here.

  4. Promote only if the preregistered gate passes.

    A candidate must beat the local holdout best under the locked rule. If the result is inconclusive or negative, do not use the slot.

  5. Build, reopen and audit the exact GeoTIFF bytes.

    Require one float32 band; exact reference shape, transform and CRS; finite in-footprint values in [0, 1]; NaN outside the official footprint. Validate after writing to catch conversion, nodata or mask errors.

  6. Only then publish a new download and submit manually.

    Use the collision-resistant filename and concise note below, link the verified file at the top of the project home, and submit from the authorized competition account. This repository does not upload or spend a slot.
